# 画面规则

这些规则来自一套三集、共 425 句的手绘讲解片，每一条都踩过坑。

## 时间（引擎已经按这些写死，`npm run check` 会拦）

1. 一个分句是一拍，这一拍的内容写在 `b(句, 分句, …)` 里。
2. 同一拍内一步接一步，同一时刻只有一支笔。
3. 铅笔 1600 设计像素/秒、手写 9 字/秒，全片固定。笔画越长画得越久。
4. 起笔时间由分句起点和 `at` 指定的口播词决定。一拍里的空余时间平均分到**步骤**之间（一个 `d()`、一个 `h()` 是一个步骤）；同一个 `d()` 里的几笔紧挨着画，中间不留空。
5. 上色 0.28 秒，不占笔的时间。整组让位（`mv`）、整组擦除（`fade`）也不占，新内容同时开画。
6. 第一个步骤指定了口播词时，最多等 0.4 秒；后面的步骤会一直等到口播词念出来。

## 校验会报的错，和怎么修

`check` 每行的"占 N%"是"从开口到画完"占这个分句口播时长的比例。它**包含步骤之间分到的空余时间**，所以有好几个步骤的拍几乎总是 95% 以上，不代表铅笔一直在动。超过 100% 也没关系，只要在下一个分句开始前 0.1 秒画完就算过。

| 报错 | 判定 | 修法 |
|---|---|---|
| 没画完就到下一句 | 画完（含上色）晚于下一个分句开始前 0.1 秒 | **只减内容**：少画几笔、框小一点、字少一点、零件 `s` 小一点。不改语速，不加停顿 |
| 开口 N 秒后才落笔 | 开口 0.5 秒后还没落笔 | 第一个步骤不要锚在句尾的词上；或者把一个不锚词的小东西放到最前面 |
| 比口播「某词」慢 | 锚在这个词上的步骤，比念到它晚了 0.25 秒以上 | 前面的步骤太多了。三种修法：把锚词对应的东西挪到前面（第一步最多等 0.4 秒）；减掉它前面的内容；或者把锚词换成本分句里更靠后、意思也对得上的词。按口播的顺序排步骤 |
| 开口 N 秒后才开始画（上一句拖过来了） | 这一拍第一步没写锚词，但上一个分句还没画完 | 先修上一个分句 |
| 画得比口播快 | 分句口播不短于 1.2 秒，而画的时间不到 60% | 画完以后画面会停住不动。把一个大的 `d()` 拆成两三个步骤（空余时间会分到步骤之间），或者给这一拍再加一点内容，或者把后半部分锚到后面的口播词上 |
| 上一句的笔还没收 | 上一个分句拖过来了 | 先修上一个分句 |
| 这一句没有画任何东西 | 这个分句没有写 `b(…)` | 每个分句都要有画面，哪怕只是一个圈、一个勾 |
| 找不到锚词 | `at` 的词不在这个分句里 | 锚词要和稿子一字不差；同一个词在一句里出现两次，会找本分句里的那一个 |

## 画什么

- **像一位画师逐步画出流程**：细节多，字少图多。不要"关键词一个个弹出来"那种做法。
- **先讲逻辑，再画比喻。** 每个机制先用带名字的方块和箭头画出因果，口播说到"我们打个比方"才画比喻里的人物。
- **画出因果，不要只贴标签。** 讲"只做一件事"，光在框里写这几个字不够，要画出旁边的手机、消息被打叉；讲"A 让 B 更容易"，要画出 B 之前难在哪、A 怎么改变了它。一个框写两个字、再连一个箭头，观众看不出因果。
- **结论那一拍最要花心思。** 观众记住的往往是最后一张画面，别让它是最简单的一张。比较两个数（1 倍和 37 倍）时，画成两样能直接比大小的东西（两根柱子、一大一小两个人），比只画一条曲线直观。
- **比例画得不真实时，写上"示意"。** 为了看得见，把小的东西放大画是可以的（10 块和 1 块按真实比例画，1 块会小到看不见），但画面角落要写"示意"两个字，免得观众当真。
- 同一处手写字不超过约 6 个字。整句话是字幕的事。
- 画不完就减内容。曾经出现过一集 86 个元素画到了下一句，观众看到的全是半成品。
- 不要给配音加停顿来等画面。试过，效果很差。

## 构图

- **用满画面。** 一个场景画完时，内容的重心应该在画面中间附近，上下左右都用到。常见的错误是全部挤在上半部分、下面空着四分之一，或者整排偏左。
- **元素要够大。** 人物 `s` 一般 1.5–2.2，物件 1.2–2，框里的字 40–60，强调的字 60–90。`s = 1` 的人物只有 60 宽，在成片里几乎看不清。
- **场景之间接得上。** 前后两个场景讲的是同一件事的两步时，不要硬切到一张新纸：用 `mv` 把前面的内容整组缩到角落，在同一张纸上接着画；后面的画面和前面的保持同样的比例和画法（比如前面用柱子高度表示钱，后面也用柱子）。
- **缩到角落的东西别缩太小。** 缩放后字号低于约 30 就认不出来了，`mv` 的缩放一般不低于 0.5。真的放不下，就在下一拍开头 `fade` 掉它，不要留一团看不清的小图。
- **一屏一个焦点。** 同时出现的东西太多，观众不知道看哪。用 `fade` 擦掉已经讲完、后面用不上的东西。
- 设计坐标 1920×1080。成片里画面缩到 90%、贴顶居中，底部 10% 专放字幕，所以内容的 y 不要超过约 1000。

## 自己看检查图

`npm run stills` 的自检**只查文字**：字压字、字出框、字出画面。下面这些它查不到，要自己逐张看：

- 线压线、形状互相遮挡（比如装饰线正好压在箭头上，看起来像双线箭头）
- 画面一半是空的，或者整体偏向一边
- 元素太小看不清
- 前面的内容挡住了后面的内容

检查图是在每个分句"下一个分句开始前 0.12 秒"截的。同一句里的分句之间，字幕一直显示到下一个分句；一句话的最后一个分句念完 0.25 秒后字幕就消失，截图时已经没有了。所以每句最后一个分句的图不带字幕，这是正常的。

检查图是成片的样子：画面缩到了 90%，1920 宽的图左右各留 96 像素。从图上量到的位置换回设计坐标：

```
x_设计 = (x_图 − 96) / 0.9
y_设计 = y_图 / 0.9
```

## 验收清单（给用户看片时对照）

- 每句话开口时，铅笔同时开始画这句的内容。
- 讲到关键词时，对应的东西正在落笔。
- 下一句开始之前，上一句已经画完，没有半成品。
- 换场景时画面是完整的。
- 逻辑够细：每一步的因果能从画面上看懂。
- 画面用满了，没有大片空白。
- 字幕不挡画面。
